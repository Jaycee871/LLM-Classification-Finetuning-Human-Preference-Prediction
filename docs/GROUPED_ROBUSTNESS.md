# Prompt-grouped validation: new independent robustness experiment

Our first successful Qwen 0.5B LoRA pilot produced **1.963875** log loss on a 1,200-row stratified validation subset, while a length-only reference fitted on the identical 2,000 original training pairs produced **1.066153**. The prior leaderboard length-only submission scored **1.06530** on a different, unknown hidden validation population. These numbers must not be conflated.

The next CPU experiment uses **all 57,477 available labeled rows** (assuming the official file is unchanged) and separates **exact normalized prompts** into non-overlapping train/test groups. We use a seeded 15% *group*-level outer holdout, then split the outer training groups again, reserving 18% for inner C selection. Only inner data select the regularization hyperparameter for the six-feature length-only classifier. After refitting on outer training groups, evaluate once on the outer held-out groups, report **log loss versus uniform and training-prior baselines**, counts, exact prompt overlap and a nonparametric row-bootstrap confidence interval for the difference.

**Critical limitations:** grouping by exact normalized prompt hash cannot remove paraphrases, near duplicates or all dataset provenance leakage. One outer split cannot establish robust uncertainty; follow-up should use multiple seeds and clustered/group bootstrap when appropriate. Repeated experimentation on the same outer split would invalidate its role as an independent test. This is a robustness check of the length-only baseline, not a causal test of verbosity, nor a direct improvement to our Kaggle score.

[Workflow](../.github/workflows/grouped-length-robustness.yml) automatically launches **only upon the deliberately named first merge commit** and can subsequently be manually rerun. It downloads official Kaggle data onto an ephemeral GitHub runner, and **publishes only aggregate JSON**, with no raw prompts, private data, row-level model outputs or tokens.
